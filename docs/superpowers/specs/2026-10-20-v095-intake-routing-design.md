# 0.9.5 子项目一：导入内容分配

状态：用户已确认细化设计。共同约束见 `2026-10-20-v095-design.md`。

## 现有接口

`ui/intake.py` 的普通预览将勾选页面合并为一个目标栏；唯一结构化 JSON 题目可明确选择整题替换。现有 `apply_intake_selection`、单栏追加、OCR 候选采用/撤销和整题 JSON 流程保留。

工作区为 `practice_store.py` 的 `practice_workspace`，保存四栏、题目设置、原始量表和题库关联；`workspace_history` 保留旧草稿。现有 `flush_workspace` 逐次写入不能直接充当新增四栏提交的原子保证。

## 用户流程

1. 在现有导入预览中增加“分配内容…”入口；文件读取和识别先沿用当前流程，本功能本身不做识别或联网。
2. 将当前勾选页面的已核对文字按原文顺序分段，显示来源文件、页码和正文。保留原段文字与段内换行，不自动改写、去重或猜测所属栏位。
3. 每段可选择题干与要求、给定材料、我的原答、参考答案或“不导入”。默认“不导入”，提供将勾选段统一指定目标的操作；一段只有一个目标，段序沿用来源顺序。需要改变段界时回原预览修订文字后重新分配，不新增复杂排版编辑器。
4. 右侧按四栏分别预览最终内容。每栏默认追加；有分配内容的栏可单独选择替换，空目标不改原栏，不能用空分配清空原答。
5. 确认写入时集中列出将替换的非空栏，明确确认且默认取消；取消分配不写数据库或修改主界面。普通单栏及结构化整题模式不受影响。

不在 0.9.5 增加跨题批量分配、自动标题分类、自动评分或 AI 内容生成。结构化 JSON 整题替换与普通文字分配互斥，避免混用缺省字段的清空语义。

## 保存和失效边界

- 分配工作只在对话框缓冲中进行，不在每次选择时写主输入框或自动草稿。
- 先记录数据库恢复代际，再冻结主界面四栏、其余题目设置、原始量表、题库关联与工作区持久化基线；覆盖确认后不得改用新的代际。
- 最终提交在一个 SQLite 事务内重新检查恢复代际/工作区基线，校验最终完整工作区，归档导入前最新草稿，再保存四栏合成后的新草稿；不能先改一栏再逐次保存。
- 提交失败或冲突时完整回滚，不出现部分栏已写入；主编辑器保留原值，分配缓冲保留，显示简短失败状态。数据库提交成功后一次性更新主界面，避免自动保存信号重复写入。
- 分配期间若其他窗口更新工作区或恢复数据库，旧预览不得覆盖新状态，须重新载入/核对。恢复前的确认不能授权恢复后的写入。
- 不改题型、考试类别、满分、字数限制、量表与方法选择；题干/材料改变导致题库关联不匹配时，沿用既有解除关联规则，不改写旧题目或旧报告。
- OCR 进行中不能打开分配。分配完成但还未最终采用前若重新识别、编辑文字、移除或排序来源页，旧分配失效并要求重新核对，不能套用过期段落。
- 沿用现有导入与草稿容量校验，在写入前校验四栏最终合计；超限拒绝提交并保留缓冲，不通过截断“成功导入”。

## 模块边界

新增独立段落/分配数据模型、四栏预览对话框和工作区事务入口；`ui/intake.py` 只负责调用和结果接入。复用工作区规范化、原草稿归档、题库关联核对及现有恢复代际，不维护第二套草稿表。

## 验证

- 多页、多文件、中文、空页和段内换行；分段顺序和内容不丢失。
- 四栏混合分配、跳过段落、默认追加、部分替换、空目标不清空，覆盖确认默认取消。
- 打开/取消/关闭零写入；OCR 忙碌阻止分配，采用新候选或修改来源后拒绝过期分配。
- 写入错误/磁盘失败/工作区超限时四栏及数据库整体不变；成功后重启读到同一完整草稿，导入前草稿仍在历史中。
- 两窗口写入或恢复发生在预览/覆盖确认期间时拒绝旧操作，不产生失效题库关联。
- 原单栏导入、JSON 整题导入、拖放、粘贴、OCR 和四个统一占位文字回归；新增功能模型调用数为 0。
