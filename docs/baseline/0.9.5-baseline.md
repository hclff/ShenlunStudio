## 语料体积构成（解释 262 MB 与 141 MB 安装包）

| 组成 | 体积 |
| --- | --- |
| `articles` 表 `data` 字段合计 | 22.1 MB |
| 其中 `body` 正文 | 9.2 MB |
| FTS5 `article_search_data`（trigram 索引） | **141.5 MB** |
| 数据库总大小 | 262.3 MB |

即：**种子库体积主要来自文章检索的三元组全文索引，而非正文本身**。`list_articles` 不触碰该索引，所以它既不影响列表刷新耗时，也不参与正文反序列化；但它直接决定了安装包体积（0.9.5 Setup 为 141,313,387 字节）。缩减索引属独立议题，本轮不改语料内容。

## 已确认的统计口径缺陷

`ui/library.py:137-139` 期望 `stats['text_bearing']`，但 `storage.py:149-158` 的 `stats()` 从不返回该键，于是取值退化为 `stats['available']`，界面"含文本"实际显示的是"可访问"条目数；`ui/library.py:146-150` 为 `'?'` 准备的兜底二次全量读取因此是**不可达代码**。

> 对计划表述的更正：先前判断的"每次刷新两次全库读取"不成立，实际是**一次**全库 JSON 反序列化 + 一处统计口径错误。批次 B 的目标改为：用摘要查询避免反序列化，并把"含文本"改为真实统计（`has_body`）。

## 测试基线

两轮全量，同一份代码：

| 运行方式 | 结果 | 耗时 |
| --- | --- | --- |
| 桌面（150% 缩放） | **1116 passed / 2 failed** | 824.34 s |
| offscreen（`QT_QPA_PLATFORM=offscreen`，dpr=1） | **1118 passed / 0 failed** | 1201.09 s |

桌面失败的两项为环境敏感，非代码回归（源码与 0.9.5 逐字节一致，且 offscreen 下全部通过）：

1. `test_visual_rubric.py::test_normal_and_min_window_keep_table_controls_reachable[size1]`：1050×720 下量表表格视口 84 px，而 150% 缩放下行高为 44 px，`84 >= 88` 差 4 px 失败。
2. `test_workflow_release_probe.py::test_workflow_probe_persists_real_artifacts_and_unique_children`：`grab()` 在 150% 缩放下输出 1575×1080，与期望的 1050×720 不符。

结论：**基线门禁必须固定 `QT_QPA_PLATFORM=offscreen`**（dpr=1，尺寸确定），桌面高缩放环境不用于判定。两项断言对 DPI 的敏感性应作为独立小修，不并入功能批次。

## 复现方式

```powershell

# 基线测试（必须 offscreen + 显式 basetemp）
$env:QT_QPA_PLATFORM='offscreen'
python -m pytest -q -p no:cacheprovider --basetemp=validation/pytest-tmp
```
